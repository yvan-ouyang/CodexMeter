# Antigravity CLI Statusline 额度接入

**状态：Final PRD（2026-11-26 独立设计挑战已收口；仅设计冻结，尚未实施或验收）**
**基线：** `035988c692cb0739b5226fe61c5a02f5693df83d`，`codex/macos14-intel-test`。
**来源：** 用户希望 Codex 与 Antigravity 在同一个 CodexMeter 菜单栏/下拉面板展示；已接受安装并运行官方 Antigravity CLI，并在真实数据探针成功后明确同意实施。

## 背景与真实证据

- 旧版 `AntigravityGeminiModelsClient` 依赖本地服务探测及已有 OAuth 配置，本机 Antigravity 2.35.2 不满足旧探测条件；原作者公开仓库仍未提交新实现。
- 已安装且经 Google 签名/Apple 公证验证的官方 `agy` 1.5.18 可在 macOS 14.6.1 Intel 启动，用户完成登录并确认 `/usage` 正常。
- [官方 Statusline 契约](https://antigravity.google/docs/cli/statusline/)（前序已读取的[官方 Markdown 正文](https://antigravity.google/docs/cli/statusline.md)）：用户级 `~/.gemini/antigravity-cli/settings.json` 的 `statusLine` 为对象；`type` 为 `command`，`command` 为字符串。CLI 在自身状态变化时以 `sh -c` 执行命令，将状态 JSON 送入 stdin，stdout 用于状态行；`enabled` 默认 true，`stack_with_default` 默认 false，设为 true 可以保留 CLI 内置状态行。CLI 最频繁约每 300 ms 调用一次，5 秒超时，连续 30 次失败会在本会话禁用脚本。无需 CodexMeter 启动或主动请求该 CLI。
- 一次 `agy --settings` 临时会话实际取得 `gemini-5h`、`gemini-weekly`、`3p-5h`、`3p-weekly` 四个窗口，包含真实非默认比例、合法绝对重置时间及 `3p-5h` 的 100% 和 Unix epoch（`1970-01-01T00:00:00Z`）占位重置时间；初始化时也出现空 `quota`。探针不发送模型消息、不改全局配置，已清理临时文件，原 CLI 会话仍存活。`--settings` 是 CLI 已确认的 session-only 覆盖，探针不能证明全局安装或既有会话热加载已验收。真实个人数据不复制到仓库。
- 套餐/桶来自官方回调；回调收到时间不是服务端查询时间。仅桌面消耗额度时，空闲 CLI 是否及时更新由官方 CLI 决定，当前未证实。

## 目标与已确认数据流

在现有 Antigravity 设置页增加一个显式、可撤销的 CLI Statusline 来源，让用户在原有菜单栏与下拉卡片看到真实额度、重置时间及最后采集时间。不主动启动 CLI、不轮询 Google、不发任何模型请求。

用户确认的原始方案图（2026-11-26，回复“可以，你做吧”）：

```text
Antigravity CLI
    │ 官方状态回调
    ▼
本地额度快照（最小字段）
    │ CodexMeter 只读加载
    ▼
已有菜单栏摘要 + 下拉面板 + 重置倒计时
```

## Scope Contract

### 必须改变

1. Antigravity 设置新增明确的“CLI Statusline”来源、安装/移除回调和可理解的状态指引；CLI 由用户正常运行、登录与刷新。
2. 官方回调只写必要的本地额度快照；CodexMeter 只读加载，独立于 Codex 网络结果；显示已获额度组、百分比、有效重置时间、来源及最近采集时间。
3. 正常关闭 CLI 时保留最后的有效快照，始终明确来源不是实况查询，数据超过既有 120 秒新鲜度口径时标记可能已过期；重新读取不刷新采集时间。首次无数据或快照损坏时明确等待/错误，不回退成其他来源。
4. 仅使用已知桶映射与真实字段。`0`、`1` 都是有效比例；不合法比例、未知桶、仅有绝对剩余量但无分母、无效重置时间不伪造数据。空初始化不覆盖同账号或来帧身份未知时的最后有效数据；已识别的账号切换或发现上次身份不可信时不把旧数据归给该账号，按下文有效/等待帧规则处理。

### 必须保护

- Codex 网络、额度、活动、成本、Radar、OpenCode Go、原 Antigravity 旧来源和通知、现有展示偏好/布局、Widget Codex 缓存均不被改造。
- 不自动更换既有用户数据来源或安装用户级回调。安装保留其他 CLI 设置及内置状态行，不覆盖用户自定义 Statusline；移除仅解除本应用配置。已有快照与 CLI 登录不受移除影响；关闭显示、切换来源不隐式修改 CLI 配置。
- 不读取 Antigravity 认证文件、不记录 OAuth/认证材料、原始回调 JSON、对话内容、工作区或 transcript；只保存额度、采集时间、可选套餐和官方账号标识（本机显示/隔离需要时）。配置与快照原子写入，实际写入失败不得报告成功。
- CLI 来源仅展示，不产生自动模型请求、Antigravity 通知/重置彩带；旧来源的这些行为不变。
- 保留 macOS 14 Intel 兼容和现有 Bundle/版本身份；无用户明确授权不提交/推送/发布，不修改全局工具链或无关工程。

### 允许触及

新增 Foundation-only Statusline 输入/输出与安装器、Swift 适配器/来源选择、`CodexMeterMain` Hook 分派、`GeminiModelsSettings`、`GeminiModelsUsageSource`、`UsageViewModel` 的 Antigravity 分支及通知来源守卫、现有设置/布局预览与 `GeminiModelsSection`、菜单栏仅 Antigravity 项的解析/标记、所需本地化、Xcode target 引用及新版 bundle 能力标记、测试与用户使用说明。相同本地快照文件为 CLI 来源唯一事实，不在 Codex 共享缓存另存第二份；不新增布局 token、其他供应商的行为分支或新的常驻进程。

### 非目标、延后与升级触发条件

- 不新增模型供应商、不自动启动/包装 CLI 调用 `/usage`、不扫描进程认证参数、不调用私有端点、不读取或复制凭据、不自动登录、不尝试桌面独立实时探测。
- 不维护多账号集合或选择器、不合并多个来源、不自动组合第三方 Statusline；同一时刻只展示最新接受的单份快照，账号切换时不保留旧账号作新账号。
- 不新增 CLI 来源的提醒/彩带、Widget 专用 Antigravity 展示、全局缓存重构、自动更新/发布改造。若需要新增这些能力或桌面持续实时来源，先确认扩大范围。
- 未知官方桶、空闲 CLI 更新时效、第三方自定义脚本组合留作后续；本机完整构建缺少现代 Xcode 时，需用户决定是否使用既有 fork CI。

## 关键契约

| 来源字段 | 转换规则 |
| --- | --- |
| `product` | 必须是 `antigravity`，只接受官方 Statusline 结构，不执行任何输入。 |
| `quota.gemini-5h` / `quota.gemini-weekly` | Gemini 模型组，分别为 5 小时/7 天窗口。 |
| `quota.3p-5h` / `quota.3p-weekly` | Claude/GPT 模型组，分别为 5 小时/7 天窗口。 |
| `remaining_fraction` | 有限 JSON 数值 0 到 1（不接受 Bool、字符串或越界值），直接映射百分比；在进入会钳制比例的既有模型前校验。缺失/错误/禁用时保持未知，不显示为 0%。 |
| `reset_time` | 有效 RFC3339 绝对时间（含时区、支持有/无小数秒），排除 Unix epoch 占位；比例与重置时间独立校验，因此 `100% + epoch` 显示 100%、重置未知。 |
| `disabled` | 明确布尔禁用的窗口不展示可用比例，标记不可用，不替代为耗尽；不能将错误类型当作有效启用。 |
| `plan_tier` / `email` | 可选套餐、账号归属，只使用来帧明确给出的非空字段，限本机数据归属和既有显示，不传到外部；不推断账号套餐或借用上次身份。 |
| 回调收到时间 | 本地 `capturedAt` 为该次接受的回调观测时间；同值的有效新回调仍是一次观测，忽略空帧或重读文件不改变时间，UI 明示不是服务端更新时间。 |

### 安装、执行、撤销与降级

- 安装区分配置状态（未安装、已安装且命令指向当前 app、可识别自有旧路径/关闭需修复、其他命令冲突、读写/结构错误）与数据状态（等待、已观测、可能过期、错误）。安装成功只意味着写入用户级配置，不能声称 CLI 正在运行、用户已登录或回调已生效。提示用户在正常 CLI 会话中加载配置/必要时正常重开 CLI；其余项目或 session-only 覆盖层自行生效，不自动探测或修改。
- 仅显式安装/修复按钮可编辑官方 `~/.gemini/antigravity-cli/settings.json` 的单个 `statusLine` 对象，写入 `type=command`、`enabled=true`、`stack_with_default=true` 和本应用自有命令，默认 padding 无需另设。安装需从实际可执行的当前 app 获取绝对 bundle 路径；按照官方 `sh -c` 语义进行路径引用（含空格、单引号），命令参数固定，不使用 stdin 或用户配置文本拼接 shell。命令先检查该 bundle 随包提供的新版本 Statusline 能力标记及可执行文件；任一不存在则立即成功退出、不启动 app，否则 `exec` 该绝对路径的专用原生入口。入口必须在正常 AppKit / updater / 网络 / Widget 等启动之前分派，独立于 Codex 活动 Hook。回调成功或忽略不需要输出额度/账号/日志到 stdout，不破坏内置状态行。
- 缺少配置（或根对象无 `statusLine`）可建立配置，重复安装幂等；只接受与自身安装器生成的完整命令契约相符的自有命令及已识别旧安装路径，不能以命令中含有产品名、参数子串或任意 shell 拼接来认领。第三方命令、结构/类型损坏、不可写文件、存在不能安全归属的配置时提示冲突/错误，不覆盖、不执行、不自动组合。仅修改自有块，其余键值保留；写前复核读取的配置是否发生变化，发现外部编辑则拒绝本次写入、由用户重试（不承诺与其他 CLI 配置编辑者的全局事务）。不备份/记录整个含未知字段的设置正文，不访问认证文件。
- 显式移除只删除可确认自有的 `statusLine` 块；已不存在视为无需移除，第三方配置不动。不删除快照、登录或切换显示来源；已打开的 CLI 可能继续使用旧会话配置，需用户按正常 CLI 流程重新加载后才停止写入。卸载/降级前建议先移除自有配置并正常重开 CLI；若使用完整旧 bundle 替换未及撤销的新版，同路径旧 app 缺能力标记，不能被回调错误启动。移动 app 后由用户显式修复，不自动写配置。旧版本不需要理解新增 CLI 快照。

### 单份本地快照及状态转换

- 仅一个本机用户私有、带版本号的 CLI Statusline 快照，约定在 `~/Library/Application Support/CodexMeter/Antigravity/cli-statusline-v1.json`；hook 与主程序用同一位置解析方式，不依赖调用时的工作目录、App Group 权限或 Widget 容器。允许最小的锁/原子临时文件而非另一份权威或历史集合；不使用原始输入文件作缓存。目录和快照按本用户私有权限创建/保存，不跟随异常文件类型到其他目的地。
- 回调只读入一个有界 JSON 对象，检查 `product` 后白名单转换四桶和可选身份。串行化读旧状态、判断接受/忽略及原子写入，以本机串行接受顺序为准（不承诺服务端事件顺序）。不等待长期锁，不超出官方 5 秒回调时限；忽略非法/无意义输入不是写入故障，落盘/权限失败可用不含敏感内容的简短错误报告，不写入半包或伪造新时间。并发及重复回调不累积历史、日志和无界 I/O。该文件是本机观察记录，不能据 `product` 或文件内容声称远端认证。

| 来帧 / 当前状态 | 处理结果 |
| --- | --- |
| 非法 JSON、错误 `product` 或错误的根/quota 结构 | 拒绝该帧，不刷新已有文件或观测时间；不能据坏帧判断账号切换。 |
| 结构合法且至少一个已知窗口含可展示比例、合法重置时间或明确禁用状态 | 作为一份完整观测替换上一份；部分未知窗口保持未知。即使账号相同也不从旧快照补桶、重置时间、套餐或身份。来帧无账号标识则此次账号未知。 |
| 结构合法但无已知有效窗口信息（空初始化、缺失或全未知/无效桶） | 没有上一份有效数据则等待；来帧同账号或无账号标识且已有有效数据则保持原观测及时间，不把初始化帧当新额度。 |
| 结构合法且明确给出另一账号（或当前仅有无法归属的未知身份样本），但无有效窗口 | 替换为该账号的等待状态，清掉旧读数；不拿未知/以前账号的额度冒充该账号。已确认的不同账号有效观测直接整体替换。 |
| 快照不存在、等待或损坏/权限/版本不可读 | 前两者展示等待，无编造比例；读取错误展示失败并不使用内存旧值或旧来源冒充当前文件。合法的新回调可重新建立有效观测；未知文件版本不能作为有效快照。 |

多个 CLI 会话可能轮流写入，既不按账号存历史，也不试图识别正在前台的 CLI 或桌面账号。可选身份表示最后接受帧的归属。该状态定义只是同一快照的内容，不新增多账号系统或轮询供应商。

### 来源隔离、读刷新及展示

- 来源选择与既有总开关/模型组/显示位置偏好正交；缺少新来源偏好键的旧用户默认原有自动探测/OAuth 来源，明确选择 CLI 才进入本地分支。异常来源值不得偷偷触发其他源。总开关关闭仍停止 Antigravity 显示及该分支读取，保留 CLI 权威文件和已安装回调（用户可显式移除）。
- 主 app 启动且已启用 CLI 来源时即加载已有文件；来源/开关变化、手动刷新及相关界面打开时只读重新加载。自动档沿用现有 30 秒/1 分钟/5 分钟频率，本地读取不等待 Codex 网络成功或受 Codex 失败阻塞；手动档无后台定时文件读取/请求，只按启动/显式交互读取。年龄标记根据当前时钟更新，即使手动档或 5 分钟档超过 120 秒也不能继续呈现为新鲜；该时间更新本身不读供应商/发请求。
- `geminiSnapshot` 等活动展示状态仅接受当前来源与当前启用代次结果；切换/关闭时立即失效旧状态、取消在途任务并在返回/保存/发布阶段复核来源及代次。CLI 选中时绝不调用 `AntigravityGeminiModelsClient`（网络失败分支也不得回填其旧数据）。`UsageSnapshot.geminiModels` / `latest-snapshot-v3.json` 仍是旧源兼容契约，可保留既有旧源缓存供显式切回，不引入 CLI 枚举值或 CLI 数据；任何 Codex 网络保存、本机统计合并、缓存恢复、设置预览不得把 CLI 写入它。回到旧来源时走现有读取语义，不使用 CLI 快照兜底；无 Codex 快照仍可显示 CLI。CLI 本地更新不为此写 Codex 缓存、调用其通知检测或重载 Widget；设置中 CLI 额度与菜单栏布局预览须随独立本地读取/发布同步，而非只监听 Codex 成功。
- CLI 模式在 `UsageNotificationController` 初始化 seed、process、持久化及异步通知交付均排除 Antigravity 旧源/CLI 事件，切入时重置 Antigravity 独立基线且不动 Codex；切回后首份成功旧源观测重新建立基线，不在 CLI、旧源或隔期缓存间比较。已生成但未投递的旧源事件需复核来源/代次；已交付的通知不回撤。用户既有通知选项不改写，提示 CLI 来源不使用它们。
- 现有模型组过滤、布局、卡片位置、百分号、颜色偏好保持。全模型菜单摘要仍按既有“优先未耗尽窗口、选实际桶”的规则显示已知值，不是聚合总额或所有模型均已耗尽的声明；缺失/禁用窗口不计为 0。下拉及设置卡片展示所选组的各真实窗口，可见 CLI 数值（含自定义环形条）须有紧凑来源/过期标识和可访问的时间说明，不强塞新布局项目或打开用户关闭的位置。卡片及预览明确 CLI Statusline、最后有效采集日期和时间、等待/错误或可能过期；账号未知不显示为上次账号或桌面同账号。时间异常（例如系统时钟回拨导致采集时间在未来）不能声称新鲜。
- 只有历史观测的有效重置时间才用于绝对时间及未到边界的倒计时；越过边界后仍保留最后比例和记录时间，提示等待 CLI 更新，不使用通用 formatter 的“已重置”文案、不自动加额度。缺失、占位或禁用显示未知/不可用（含进度条和无障碍，不填 0%）；CLI 的 Pace/预计耗尽等仅在比例和重置时间有效、时间仍可信且满足既有计算条件时以该观测为依据提供参考；过期或已达边界时不继续生成/推进预测，旧来源和其他供应商的格式器行为不变。

## 验收引用与成功标准

独立设计挑战收口后建立同级 `acceptance-matrix.md` 与小型实施计划。重点覆盖四桶映射、未知/占位、0 与 100、部分与空帧、账号切换、并发原子替换及错误恢复、回调安装冲突/保全/撤销/降级 guard、CLI 模式零旧来源请求及 Codex 失败时独立刷新、源切换晚到结果、旧共享缓存与通知不回归、菜单/下拉/设置预览的来源/时间/过期和未知值，以及 macOS 14 Intel 完整构建。正式真实回调验证必须由用户正常使用已登录 CLI（例如正常打开 /usage）产生，验证的是产品的实际安装与菜单栏/下拉展示，不启动后台 agy 探测、不写入真实个人数据作为测试夹具。

非阻断假设与收口：官方 CLI 空闲/桌面独立消耗时的更新频率未知；以本地回调时间和过期提示作为明确边界，不用主动查询补齐。原生入口须在已知耗时上限内轻量执行，若真实 CLI 不加载用户级配置或触发超时，先据官方配置/运行状态修复，不引入常驻服务或私有接口。独立 Foundation 核心可先测试，现代 Xcode 完整构建及 Intel 装包、真实界面和回调验收仍需后续证据；本机缺失 Xcode 不是设计阻断，未经用户授权不自行使用 fork CI 的 commit/push。
